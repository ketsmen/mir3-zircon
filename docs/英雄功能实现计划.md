# Hero 分支完整英雄系统实现计划

## 摘要

在 `Hero` 分支实现 Mir2 英雄系统到 Mir3 Zircon 的完整可用版本：英雄创建、管理、切换、召唤/收回、跟随与战斗 AI、独立装备/库存/技能/经验/升级、自动喝药、客户端实体渲染和英雄 UI。

核心架构采用文档推荐方案：`HeroObject` 直接继承 Mir3 的 `MapObject`，不引入 `HumanObject`，不重构 `PlayerObject` 继承体系。Mir2 代码作为行为参考，Mir3 代码按现有 MirDB、反射网络包、DX UI、通用物品格系统落地。

## 关键变更

- 共享层新增英雄契约：`ObjectType.Hero = 8`，追加 `GridType.HeroInventory/HeroEquipment/HeroHPItem/HeroMPItem`，新增 `HeroSpawnState`、`HeroBehaviour`、`NewHeroResult`。
- 新增客户端共享数据：`ClientHeroInformation` 用于英雄列表摘要，`ClientUserHero` 用于完整英雄状态，包含基础信息、HP/MP、经验、属性、装备、库存、魔法、自动喝药配置。
- 网络包必须全部直接继承 `Packet`，不能继承 `ObjectPlayer`，因为 Mir3 包注册只收集 `BaseType == Packet` 的类型。
- 新增客户端包：`NewHero`、`ChangeHero`、`ToggleHeroSpawn`、`SetHeroBehaviour`、`SetHeroAutoPot`。物品移动复用并扩展现有 `MoveItem/ItemSplit/RemoveItem/UseItem/ItemChanged/ItemsChanged`，不新增 Mir2 风格的重复传输包。
- 新增服务端包：`ObjectHero`、`HeroInformation`、`HeroHealthChanged`、`GainHeroExperience`、`HeroLevelChanged`、`NewHero`、`ChangeHero`、`ManageHeroes`、`UpdateHeroSpawnState`、`SetHeroBehaviour`、`SetHeroAutoPot`。
- `StartInformation` 增加当前英雄、英雄列表、英雄最大数量、英雄行为模式和召唤状态，保证登录后客户端一次性得到完整英雄初始状态。

## 实现步骤

### 1. 数据层和持久化

- 新建 `HeroInfo : DBObject`，标记 `[UserObject]`，由 `CharacterInfo` 聚合拥有。
- `HeroInfo` 字段固定为：所属角色、名称、职业、性别、等级、经验、当前 HP/MP、发型/发色、品质、自动喝药开关、HP/MP 药品索引、HP/MP 阈值、创建时间、删除标记、排序槽位。
- `HeroInfo.Items` 保存英雄物品，slot `< Globals.EquipmentOffSet` 为英雄背包/腰带，slot `>= Globals.EquipmentOffSet` 为英雄装备。
- `HeroInfo.Magics` 保存英雄技能，不能复用 `CharacterInfo.Magics`。
- `CharacterInfo` 新增 `Heroes`、`CurrentHero`、`HeroSpawned`、`HeroBehaviour`。
- `UserItem` 新增 `Hero` 关联，`UserMagic` 新增 `Hero` 关联，并在 `OnDeleted`、`RemoveItem`、孤儿诊断中补齐清理逻辑。
- `SEnvir` 注册 `HeroInfoList`，初始化、清空、诊断和保存流程与 `UserCompanionList` 同级。

### 2. 服务端核心

- 新建 `HeroObject : MapObject`，包含 `Owner`、`Info`、`Inventory`、`Equipment`、`MagicObjects/Magics`、`Target`、`Pets`、AI 时间戳、自动喝药时间戳。
- 新建 `WarriorHero`、`WizardHero`、`TaoistHero`、`AssassinHero`，按 Mir2 子类迁移 AI 决策顺序，但技能名映射到 Mir3 当前 `MagicType`。
- 新建 `HeroFactory`：按 `MirClass` 创建对应英雄对象。
- 英雄属性计算复制 Mir3 玩家的人形属性规则：基础职业等级属性 + 装备属性 + 技能被动 + Buff；不改 `PlayerObject.RefreshStats`。
- 英雄装备校验复用玩家装备规则：职业、性别、等级、绑定、耐久、装备槽正确性；禁止伴侣专属物品进入英雄装备。
- 英雄 AI 固定行为：
  - `Attack`：主动搜索可攻击目标并战斗。
  - `CounterAttack`：只攻击正在攻击主人/英雄的目标，或主人当前攻击目标。
  - `Follow`：只跟随主人，不主动攻击。
  - `Custom`：保留协议值，服务端暂按 `Attack` 处理，UI 文案标注为自定义。
- 战斗目标判断必须让英雄继承主人 PK、组队、公会、战争、宠物所有权规则；怪物、玩家、宠物攻击英雄时也必须正确反击和归属经验。
- 经验归属：英雄造成击杀时英雄获得英雄经验；主人参与组队/宠物经验逻辑不被破坏。英雄升级发送 `HeroLevelChanged`，刷新属性并同步客户端。
- 召唤生命周期：登录、登出、死亡、地图切换、断线、召回、切换英雄都必须调用统一 `SummonHero/DespawnHero`；英雄距离主人过远时传送到主人身后。
- `MapInfo` 新增 `NoHero` 布尔字段；进入禁用地图自动收回英雄，离开后按 `HeroSpawned` 状态恢复。
- `Config` 新增：`AllowNewHero`、`HeroRequiredLevel`、`HeroMaxCount = 9`、`HeroInventorySize = 42`、`HeroBeltSize = 2`、`HeroExpRate`、`HeroReviveDelay`。

### 3. 玩家集成和协议处理

- `PlayerObject` 新增当前运行时 `HeroObject Hero`，并实现 `NewHero`、`ChangeHero`、`ToggleHeroSpawn`、`SetHeroBehaviour`、`SetHeroAutoPot`、`SendHeroInformation`。
- 英雄创建校验：服务器开关、角色等级、最大数量、名称合法、名称不能与角色名或其他英雄名重复、职业只允许 Warrior/Wizard/Taoist/Assassin。
- 英雄默认创建后等级 1、HP/MP 满、背包 42 格、装备数组使用 `Globals.EquipmentSize`，初始当前英雄为空时自动设为当前英雄。
- `SConnection` 增加新增客户端包处理；所有处理都要求 `Stage == GameStage.Game`。
- 扩展 `ItemMove/ItemSplit/UseItem/RemoveItem/CanGainItems/CanUseItem/DamageItem` 中的 grid switch，支持 `HeroInventory/HeroEquipment/HeroHPItem/HeroMPItem`。
- 自动喝药只消耗英雄背包内药品，按配置阈值和冷却运行；药品不存在或数量为 0 时关闭对应药品索引并同步客户端。
- 增加中文/英文消息：创建失败原因、英雄已召唤/已收回、地图禁止英雄、英雄死亡、英雄升级、自动喝药配置变更。

### 4. 客户端实体和 UI

- 新建 `Client.Models.HeroObject : PlayerObject`，使用 `ObjectHero` 数据绘制英雄外观、名字、主人名、血条；名称颜色固定为明显区分玩家的颜色。
- `CConnection` 增加 `ObjectHero` 创建和英雄包处理；`MapControl.CanAttack`、鼠标选择、目标框、血条、对象移除支持 `ObjectType.Hero`。
- `GameScene` 新增 `CurrentHero`、`Heroes`、`HeroSpawnState`、`HeroBehaviour`，并在登录 `StartInformation` 初始化。
- 新建英雄 UI：英雄状态面板、英雄创建窗口、英雄管理窗口、英雄库存/腰带窗口、英雄装备窗口、行为模式面板、自动喝药配置区。
- 英雄 UI 复用现有 `DXItemGrid/DXItemCell/CharacterDialog/InventoryDialog` 风格，所有用户可见文案优先简体中文。
- `DXItemCell` 支持英雄格子拖拽、双击使用、拆分、锁定、装备穿戴、物品提示；现有背包、仓库、伴侣流程不改变。
- 菜单和快捷键增加英雄入口：打开英雄面板、英雄背包、英雄装备、召唤/收回、行为模式切换。
- 英雄技能 UI 首版只展示英雄已学技能、等级和经验；自动施放由服务端 AI 决定，不提供手动施法。

### 5. 技能实现策略

- 第一轮实现完整英雄系统闭环，不重构 190+ 个 `MagicObject`。
- 英雄主动技能先实现职业核心技能映射：
  - 战士：基础近战、刺杀/半月/烈火类攻击、自我增益类。
  - 法师：火球、雷电、冰系单体、火墙/冰雨类范围、魔法盾。
  - 道士：治疗、群疗、净化、毒/符类攻击、防御增益、召唤类。
  - 刺客：近战连击、隐身/加速、自我增益、远刺类技能。
- 每个英雄技能通过 `HeroMagicService` 包装为小型施法动作，内部复用 `MapObject` 伤害、Buff、Poison、召唤和广播包；不要把 `MagicObject.Player` 改成通用接口。
- 后续如需全量玩家技能复用，再单独做 `MagicObject` 施法上下文重构；本计划不把该重构作为英雄系统首版阻塞项。

## 测试计划

- 编译：执行 `dotnet build "Zircon Server.sln"`，确保 Client、Server、ServerCore、LibraryCore、ServerLibrary 全部通过。
- 数据迁移：旧数据库无英雄数据时可正常启动、登录、保存；新增英雄后重启仍保留英雄、装备、库存、技能、当前英雄和召唤状态。
- 创建/管理：测试合法创建、重名、非法名、等级不足、关闭创建、超过 9 个、切换当前英雄。
- 召唤生命周期：登录自动恢复、手动召唤/收回、切图、死亡、断线、禁用地图、英雄死亡复活延迟。
- AI 行为：四职业分别测试主动、反击、跟随；不会攻击队友、公会、和平模式保护目标；能攻击怪物和合法敌对目标。
- 物品：玩家背包与英雄背包互移，英雄穿脱装备，拆分堆叠，使用药品，自动喝药，死亡/登出不丢失。
- 经验升级：英雄击杀怪物获得经验、升级刷新属性、客户端经验条和等级同步。
- 客户端 UI：英雄实体显示、主人名、血条、创建窗、管理窗、装备窗、背包窗、自动喝药配置、快捷键和菜单入口。
- 回归：现有玩家、宠物、伴侣、交易、仓库、邮件、公会仓库、精炼、自动喝药不因新增 `GridType` 分支退化。

## 明确假设

- 只实现 Mir3 已有四职业：Warrior、Wizard、Taoist、Assassin；不实现 Mir2 Archer。
- 英雄归属到角色 `CharacterInfo`，不是账号共享。
- 英雄最多 9 个，当前英雄同时只能召唤 1 个。
- 英雄背包总容量 42，其中前 2 格作为英雄腰带/自动药品候选，UI 展示为 2 格腰带 + 40 格背包。
- `Custom` 行为保留协议兼容，首版按 `Attack` 执行。
- Mir2 的封印英雄 `SealCount/SealedHero` 不纳入首版完整系统，除非后续单独提出封印玩法。
