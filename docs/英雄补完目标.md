# 英雄补完目标

本文用于记录当前英雄系统已经可用后，仍建议继续补强的功能点。目标不是重做现有实现，而是把“可用”推进到“更完整、更耐玩、更好维护”。

## P0

### 1. 英雄技能系统补完整

- 已补齐基础闭环：英雄技能书学习/高阶升级、技能经验成长、`S.HeroMagicLeveled` 同步、客户端技能页展示等级/经验/未学习/满级状态。
- 英雄 AI 已能按已学技能、职业、等级、MP、冷却和自定义技能配置选择攻击/支援技能。
- 后续仍可深化为独立技能管理面板或更细的施法策略，但当前学习、成长、展示和自动使用路径已经可回归。

### 2. 英雄主动使用物品补齐

- 已补齐当前安全白名单：英雄背包右键支持药品/经验药、属性药水 Buff、净化药、满恢复类道具和技能书。
- 服务端通过 `HeroObject.CanUseItem()` 明确拒绝传送、修理油、洗点、PK、救赎、伴侣重置、仓库扩容、改名/变性等玩家或账号专属道具。
- 使用后复用 `C.ItemUse`、`S.ItemChanged` 和 `S.HeroInformation` 同步数量、属性、HP/MP、经验、负重和技能状态。
- 英雄属性药水 Buff 为临时运行期效果，避免没有英雄 Buff 持久关联时写出无法归属的数据；切换/重登后需要重新使用。

### 3. 多英雄管理补完整

- 已补齐创建、切换、列表摘要之外的管理维度：
  - 删除英雄：服务端会先要求清空英雄背包和装备，避免物品随软删除英雄隐藏。
  - 重命名英雄：沿用角色名规则，并检查全局角色名和英雄名冲突。
  - 调整英雄排序/槽位：客户端上移/下移，服务端重新压缩为连续 `Slot`。
  - 查看非当前英雄详情：通过 `InspectHero` 请求完整资料，`HeroInformation.Inspect=true` 只刷新查看面板，不切换当前英雄。
- 非当前英雄详情为只读快照；背包、装备、整理、自动喝药和召唤/行为控制仍只允许当前英雄操作。

## P1

### 4. `Custom` 行为明确化（已补独立策略）

- 客户端保留 `HeroBehaviour.Custom` 入口，按钮和模式标签使用中性 `自定义` 文案。
- `HeroCustomBehaviourProfile` 已提升为角色级持久化策略，并通过 `StartInformation`、`ManageHeroes`、`SetHeroBehaviour` 同步到客户端。
- 客户端 `自定义` 按钮已支持切换和轮换：非 Custom 时切入 Custom，已在 Custom 时按三种策略循环切换。
- 当前支持三种策略：
  - `AttackCompatible`：旧主动兼容行为，会主动搜怪、重选近怪，并响应主人攻击目标。
  - `GuardOwner`：护主策略，不主动搜怪，不跟随主人主动攻击，只响应主人或英雄被攻击。
  - `FocusOwnerTarget`：集火策略，不主动搜怪，主人攻击合法目标时直接接管该目标。
- 服务端切换提示会显示当前自定义策略，例如 `自定义(护主)` 或 `自定义(集火主人目标)`。
- `Attack`、`CounterAttack`、`Follow` 的按钮文案、回包同步和目标清空逻辑保持独立。

### 5. 英雄腰带/药品栏体验统一

- 已明确收敛为“英雄背包 + HP/MP 自动喝药引用槽”。
- 客户端英雄背包仍是统一 `HeroInventory`，`HeroHPItem` / `HeroMPItem` 只保存药品模板索引，不是独立存储格。
- 服务端自动喝药实际消耗当前英雄背包中的同类药品；药品被移走、用完或不再满足 HP/MP 恢复条件时会清空设置并回包同步。
- 计划文档中早期“2 格腰带”的描述后续可整理为历史设计说明，当前实现不再按独立腰带推进。

### 6. 英雄 AI 再深化

- 已补齐第一轮策略深化：远程英雄可在目标贴脸且具备施法条件时尝试后撤，法师会略微提高与主人的跟随距离。
- 道士治疗目标已区分主人危急、自身危急、主人低血和自身低血，减少低血支援时的机械优先级。
- 已补第二轮近战评分微调：战士更偏向主人附近和可贴身目标，刺客更偏向近距离与低血目标。
- 已补近战技能扩展：战士会周期触发 `Slaying` 和 `FlamingSword`，刺客会周期触发 `Discipline` 并保留 `Hemorrhage` 流血优先级。
- 已补法师范围技能选点和冷却：`IceStorm`、`FireStorm` 会按目标密度选点，`FireWall` 可周期铺场，`MagicShield` 会自动维护。
- 已补法师连锁/弹射第一批：英雄 AI 会在多目标场景下优先尝试 `ChainLightning` 和 `FireBounce`，服务端补齐延迟命中、后续连锁/弹射目标、技能经验和客户端 `ObjectMagic`/`ObjectProjectile` 表现包复用。
- 暂留边界：`ElectricShock` 的玩家实现包含震慑、驯服、宠物归属和里程碑逻辑，不能按纯伤害弹射技能直接接给英雄；`LightningBall` 属于单体投射技能，不纳入本轮“连锁/弹射”目标。
- 已补道士辅助 Buff 主动维护：会为主人/自身轮换补 `Resilience`、`MagicResistance`、`ElementalSuperiority`、`BloodLust`，并按职业跳过不合适的输出 Buff。
- 后续仍可继续补：
  - 道士净化和群疗细化

### 7. 客户端英雄 UI 拆分整理

- 已做轻量整理：角色页展示英雄品质，底部管理区显示当前英雄在列表中的位置，重命名/删除/上移/下移归到同一块管理信息下。
- 英雄角色页已新增“培养”按钮：左键预览当前英雄品质培养消耗，右键先请求服务端结构化预览并弹确认窗，点确认后才培养；缺能力连接会回退到服务端 `@PROMOTEHEROGRADE` 聊天命令闭环。
- 品质标签已显示当前基础属性加成，例如 `品质: 精良(+10%)`，让玩家能直接看到品质成长收益。
- 后续若继续扩展，建议拆成更清晰的页面或面板：
  - 英雄状态
  - 英雄背包/装备
  - 英雄技能
  - 自动喝药
  - 多英雄管理

### 8. 服务端英雄配置面板补齐

- 品质培养配置建议、保护材料模式取舍和调参顺序已整理为 [英雄品质培养配置说明.md](./英雄品质培养配置说明.md)。

  - `HeroGradePromoteEnabled`

  - `HeroGradePromoteBaseCurrencyAmount`
  - `HeroGradePromoteSuccessRate`
  - `HeroGradePromoteEventCostRate`
  - `HeroGradePromoteEventSuccessBonus`
  - `HeroGradePromoteEventEnd`

## P2

### 9. 英雄成长深度

- 已让 `Grade` 从展示字段推进为品质成长雏形：品质会按 `HeroGradeStatBonusRate` 放大基础 HP/MP、命中、敏捷、物防、魔防和攻魔道。
- 品质成长只作用于基础属性，不放大装备、套装、Buff 或被动技能，避免高品质英雄在临时效果叠加下失控。
- 新英雄默认品质、最高品质和每级加成可通过服务端配置调整；GM 可用 `@SETHEROGRADE <品质>` 或 `@SETHEROGRADE <角色名> <品质>` 调整当前英雄品质。
- 已新增玩家培养入口 `@PROMOTEHEROGRADE`：消耗金币提升当前英雄 1 级品质，金币费用为 `ceil(HeroGradePromoteBaseGoldCost * 下一品质等级 * HeroGradePromoteGoldCostMultiplier / 100 * (1 + HeroGradePromoteCostGrowthRate / 100) ^ 当前品质 * HeroGradePromoteEventCostRate / 100)`。
- 品质培养已支持材料化：可配置额外物品索引/基础数量和额外货币索引/基础数量，材料/货币消耗为 `ceil(基础数量或金额 * 下一品质等级 * (1 + HeroGradePromoteCostGrowthRate / 100) ^ 当前品质 * HeroGradePromoteEventCostRate / 100)`；保护材料数量仍按固定配置消耗，不吃成长率和活动消耗倍率。
- 品质培养已支持成功率、活动加成、失败补偿和保护材料：失败补偿为 `min(当前连败次数 * HeroGradePromoteFailureBonusRate, HeroGradePromoteFailureBonusMax)`，有效成功率为 `HeroGradePromoteSuccessRate + HeroGradePromoteEventSuccessBonus + 失败补偿` 后夹到 0 到 100；保护材料足量时根据 `HeroGradePromoteProtectionConsumeOnFailureOnly` 决定“启用即消耗保底”或“自然失败时才消耗并保底成功”；失败时品质不降低。
- 品质培养已支持聊天预览：`@PROMOTEHEROGRADE preview` 或 `@PROMOTEHEROGRADE 预览` 会显示下一品质、成功率、本档成长倍率、预计消耗、资源是否足够和保护材料状态。
- 新客户端已支持结构化品质培养预览：英雄角色页“培养”左键只看预览，右键拉取服务端预览并二次确认；英雄页和预览会显示活动消耗倍率、成功率加成、剩余时间、本次基础属性加成变化、有效成功率拆解和当前补偿次数，旧端或缺能力连接会回退到聊天预览和聊天命令。
- GM 可用 `@HEROGRADECOSTS` 快速查看当前全局品质培养配置、逐档消耗和累计消耗，便于和配置编辑器表格试算结果交叉对账。
- GM 可用 `@HEROGRADESTATE [角色名] [槽位]` 查看在线目标当前英雄或指定槽位英雄品质、下一档收益、资源差额和保护材料状态。
- GM 可用 `@HEROGRADEEVENT` 查看当前品质培养活动参数和剩余时间；`@HEROGRADEEVENT <消耗倍率> <成功率加成> [持续分钟] [save]` 可在线调整活动消耗、成功率加成和自动到期时间，`@HEROGRADEEVENT preset [名称] [持续分钟] [save]` 可列出或套用配置模板，`@HEROGRADEEVENT reset [save]` 可恢复默认并公告在线玩家。
- 品质培养失败、资源不足和成功提示会附带简短“下一步建议”，帮助玩家知道是补金币、补材料、准备保护材料，还是继续预览下一档。
- 品质培养失败补偿按英雄单独累计，真实失败加 1，成功或 GM 手动设置品质后清零。
- 后续仍可考虑：
  - 资质
  - 成长曲线
  - 封印
  - 培养路线

### 10. 提示和日志再补强

- 已补强英雄装备/使用物品失败原因、切换英雄提示、自动喝药无效设置提示和未配置药品提示。
- 手动召唤英雄时若当前地图禁召，会保留召唤意图并提示离开后尝试恢复，和地图切换禁召提示保持一致。
- 品质培养每次实际尝试都会写入 `[HeroGradePromote]` 审计日志，记录角色、英雄、前后品质、成功率、自然成功、保护消耗、保护保底、保护策略和实际消耗。
- 后续仍可继续增强：
  - 英雄复活和自动恢复召唤意图的更细日志
  - 英雄战斗目标切换的调试级日志
  - 自定义策略生效状态提示

### 11. 共享枚举兼容性守则

- 英雄系统新增了 `GridType`、`ObjectType`、`KeyBindAction` 等共享枚举值。
- 后续继续补功能时，应优先把新增枚举追加到末尾，避免改变旧客户端设置、快捷键、物品链接或数据库中已保存的枚举数值。
- 如果确实必须插入枚举中间，需要同步提供迁移说明或兼容转换逻辑。

### 12. 实机联调回归清单固化

- 已固化为 [英雄实机回归清单.md](./英雄实机回归清单.md)。
- 清单覆盖多英雄管理、召唤生命周期、物品链路、自动喝药、技能战斗和敌我过滤。
- 后续每轮英雄改动建议至少执行对应章节，并保留 `git diff --check` 与构建验证结果。
