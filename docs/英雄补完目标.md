# 英雄补完目标

本文用于记录当前英雄系统已经可用后，仍建议继续补强的功能点。目标不是重做现有实现，而是把“可用”推进到“更完整、更耐玩、更好维护”。

## P0

### 1. 英雄技能系统补完整

- 已补齐基础闭环：英雄技能书学习/高阶升级、技能经验成长、`S.HeroMagicLeveled` 同步、客户端技能页展示等级/经验/未学习/满级状态。
- 英雄 AI 已能按已学技能、职业、等级、MP、冷却和自定义技能配置选择攻击/支援技能。
- 后续仍可深化为独立技能管理面板或更细的施法策略，但当前学习、成长、展示和自动使用路径已经可回归。

### 2. 英雄主动使用物品补齐

- 已补齐当前安全白名单：英雄背包右键支持药品/经验药、属性药水 Buff、净化药、满恢复类道具和技能书。
- 服务端通过 `HeroObject.CanUseItem()` 明确拒绝传送、修理油、洗点、PK、救赎、伴侣重置、仓库扩容、改名/变性等玩家或账号专属道具。
- 使用后复用 `C.ItemUse`、`S.ItemChanged` 和 `S.HeroInformation` 同步数量、属性、HP/MP、经验、负重和技能状态。
- 英雄属性药水 Buff 为临时运行期效果，避免没有英雄 Buff 持久关联时写出无法归属的数据；切换/重登后需要重新使用。

### 3. 多英雄管理补完整

- 已补齐创建、切换、列表摘要之外的管理维度：
  - 删除英雄：服务端会先要求清空英雄背包和装备，避免物品随软删除英雄隐藏。
  - 重命名英雄：沿用角色名规则，并检查全局角色名和英雄名冲突。
  - 调整英雄排序/槽位：客户端上移/下移，服务端重新压缩为连续 `Slot`。
  - 查看非当前英雄详情：通过 `InspectHero` 请求完整资料，`HeroInformation.Inspect=true` 只刷新查看面板，不切换当前英雄。
- 非当前英雄详情为只读快照；背包、装备、整理、自动喝药和召唤/行为控制仍只允许当前英雄操作。

## P1

### 4. `Custom` 行为明确化（已采用说明方案）

- 审查结果：客户端保留 `HeroBehaviour.Custom` 入口；服务端 `ProcessSearch()`、`ReconsiderCloserMonsterTarget()`、攻击与自定义技能追击路径整体仍按主动兼容语义执行。
- 低风险落地方案：暂不改变 AI 策略，避免影响既有战斗手感；客户端按钮、当前模式标签、悬浮提示和服务端切换提示统一说明 `Custom` 当前按主动执行。
- 服务端已预留 `Config.HeroCustomBehaviourProfile` 扩展点，当前唯一配置值为 `AttackCompatible`，语义仍是按主动兼容执行。
- 回归点：
  - 英雄窗口按钮显示 `自定=主动`，悬停提示说明尚未提供独立策略。
  - 切换到 `Custom` 后，模式标签显示 `模式: 自定义(按主动执行)`，高亮仍落在 `Custom` 按钮。
  - 服务端系统消息显示 `英雄模式已切换为自定义(按主动执行)。`
  - `Attack`、`CounterAttack`、`Follow` 的按钮文案、回包同步和目标清空逻辑不应变化。

### 5. 英雄腰带/药品栏体验统一

- 计划文档里有英雄腰带概念，但当前 UI 更像一块统一背包区。
- 建议明确：
  - 是保留 2 格腰带独立展示
  - 还是统一为英雄背包加自动喝药槽
- 关键是让常量、服务端规则和客户端表现保持一致。

### 6. 英雄 AI 再深化

- 已补齐第一轮策略深化：远程英雄可在目标贴脸且具备施法条件时尝试后撤，法师会略微提高与主人的跟随距离。
- 道士治疗目标已区分主人危急、自身危急、主人低血和自身低血，减少低血支援时的机械优先级。
- 后续仍可继续补：
  - 战士技能更丰富
  - 刺客行为更贴近职业特性
  - `HeroCustomBehaviourProfile` 增加真正的独立策略枚举

### 7. 客户端英雄 UI 拆分整理

- 已做轻量整理：角色页展示英雄品质，底部管理区显示当前英雄在列表中的位置，重命名/删除/上移/下移归到同一块管理信息下。
- 后续若继续扩展，建议拆成更清晰的页面或面板：
  - 英雄状态
  - 英雄背包/装备
  - 英雄技能
  - 自动喝药
  - 多英雄管理

### 8. 服务端英雄配置面板补齐

- 已通过 `Server.WinForms.ConfigEditorForm` 的“英雄”分组暴露当前英雄配置，让 GM/服主无需直接编辑 `Server.ini`。
- 当前英雄分组覆盖：
  - `AllowNewHero`
  - `HeroRequiredLevel`
  - `HeroMaxCount`
  - `HeroReviveDelay`
  - `HeroSearchRange`
  - `HeroPursuitRange`
  - `HeroCustomBehaviourProfile`
  - `HeroExperienceRate`
- 保存时会校验英雄创建等级、数量上限、复活延迟、搜索距离、追击距离和经验倍率边界。

## P2

### 9. 英雄成长深度

- 客户端英雄角色页已显示 `Grade` 对应的品质名称和颜色，目前仍是展示/预留字段，不改变属性成长。
- 后续可考虑：
  - 资质
  - 成长
  - 封印
  - 培养路线

### 10. 提示和日志再补强

- 现有提示已经覆盖一部分关键边界。
- 仍可继续增强：
  - 英雄装备不满足条件的原因提示
  - 切换英雄后的自动召唤提示
  - 英雄背包负重不足的预判提示
  - 更细的自动喝药和复活日志

### 11. 共享枚举兼容性守则

- 英雄系统新增了 `GridType`、`ObjectType`、`KeyBindAction` 等共享枚举值。
- 后续继续补功能时，应优先把新增枚举追加到末尾，避免改变旧客户端设置、快捷键、物品链接或数据库中已保存的枚举数值。
- 如果确实必须插入枚举中间，需要同步提供迁移说明或兼容转换逻辑。

### 12. 实机联调回归清单固化

- 已固化为 [英雄实机回归清单.md](./英雄实机回归清单.md)。
- 清单覆盖多英雄管理、召唤生命周期、物品链路、自动喝药、技能战斗和敌我过滤。
- 后续每轮英雄改动建议至少执行对应章节，并保留 `git diff --check` 与构建验证结果。
