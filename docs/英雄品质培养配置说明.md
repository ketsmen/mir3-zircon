# 英雄品质培养配置说明

本文给服主和 GM 快速对齐英雄品质培养参数。实际扣费以服务端 `PromoteHeroGrade()` 实时校验为准，配置编辑器“品质试算”、`@HEROGRADECOSTS` 和玩家预览都复用同一套计算规则。

## 核心公式

- 金币：`ceil(HeroGradePromoteBaseGoldCost * 下一品质等级 * HeroGradePromoteGoldCostMultiplier / 100 * 成长倍率 * HeroGradePromoteEventCostRate / 100)`
- 材料：`ceil(HeroGradePromoteBaseItemCount * 下一品质等级 * 成长倍率 * HeroGradePromoteEventCostRate / 100)`
- 货币：`ceil(HeroGradePromoteBaseCurrencyAmount * 下一品质等级 * 成长倍率 * HeroGradePromoteEventCostRate / 100)`
- 成长倍率：`(1 + HeroGradePromoteCostGrowthRate / 100) ^ 当前品质`
- 失败补偿：`min(当前连败次数 * HeroGradePromoteFailureBonusRate, HeroGradePromoteFailureBonusMax)`
- 有效成功率：`clamp(HeroGradePromoteSuccessRate + HeroGradePromoteEventSuccessBonus + 失败补偿, 0, 100)`
- 保护材料：固定使用 `HeroGradePromoteProtectionItemCount`，不吃成长倍率。

`HeroGradePromoteCostGrowthRate` 运行期会夹到 `0..1000`。例如成长率 `50` 时，普通到优秀倍率是 `x1`，优秀到精良倍率是 `x1.5`，精良到卓越倍率是 `x2.25`。

## 推荐区间

- `HeroGradePromoteBaseGoldCost`：建议先按服务器中期玩家 30 到 60 分钟可获得金币量设置，再用“品质试算”看累计金币是否过陡。
- `HeroGradePromoteGoldCostMultiplier`：建议 `50..300`。低倍率适合快节奏服，高倍率适合把品质培养作为长期金币回收。
- `HeroGradePromoteCostGrowthRate`：建议 `0..100` 起步。超过 `200` 后高品质档位会迅速变成指数消耗，适合只想开放少数高品质英雄的环境。
- `HeroGradePromoteEventCostRate`：默认 `100`。活动期可设为 `50..90` 降低消耗；设为 `0` 等于免费培养，需要谨慎。
- `HeroGradePromoteEventSuccessBonus`：默认 `0`。活动期建议 `5..20`，配合消耗倍率能做出更直观的福利。
- `HeroGradePromoteEventEnd`：默认 `DateTime.MinValue`，表示不自动到期。通过 `@HEROGRADEEVENT` 传持续分钟数时会自动写入内存中的结束时间。
- `HeroGradePromoteEventSaveOnExpire`：默认 `false`。只有使用 `@HEROGRADEEVENT ... save` 并设置持续时间时才建议为 `true`，表示活动到期恢复默认后同步写回 `Server.ini`。
- `HeroGradePromoteEventPresets`：活动模板配置，格式为 `name=costRate,successBonus,durationMinutes`，多条用分号分隔；默认包含 `weekend=80,10,2880`、`boost=100,10,120`、`discount=80,0,120`。
- `HeroGradePromoteFailureBonusRate`：默认 `0`。建议 `5..15`，让连续失败逐步接近保底；成功后连败次数会清零。
- `HeroGradePromoteFailureBonusMax`：默认 `100`。建议 `20..50`，限制连败补偿最高可提供多少额外成功率；设为 `0` 等于关闭失败补偿。
- `HeroGradePromoteBaseItemCount` / `HeroGradePromoteBaseCurrencyAmount`：建议只选择一种作为主门槛，另一种保持低额或关闭，避免玩家同时被多个系统卡住。
- `HeroGradePromoteSuccessRate`：建议 `60..100`。如果低于 `50`，建议同时配置保护材料，减少连续失败带来的挫败感。
- `HeroGradeStatBonusRate`：建议 `3..8`。该值放大基础属性，不放大装备、Buff 或被动技能。

## 保护材料模式

`HeroGradePromoteProtectionConsumeOnFailureOnly=false`：

- 保护材料足量时，确认培养后立即消耗，并保证本次成功。
- 适合把保护材料作为明确的“保底券”售卖或投放，玩家预期最稳定。
- 保护材料消耗量更可控，资源回收更直接。

`HeroGradePromoteProtectionConsumeOnFailureOnly=true`：

- 先按成功率自然判定；自然失败时才消耗保护材料并保底成功。
- 自然成功不会消耗保护材料，适合偏友好的长期养成节奏。
- 高成功率配置下保护材料消耗会明显降低，投放量需要相应收紧。

## 对账入口

- 配置编辑器“品质试算”：读取当前窗口里的未保存配置，显示逐档消耗和累计金币、累计材料、累计货币；可选择起始品质和目标品质，只查看指定区间成本。
- `@HEROGRADECOSTS`：在游戏内输出全局逐档消耗、累计消耗、活动消耗倍率、活动成功加成、每次失败补偿和补偿上限。
- `@HEROGRADESTATE [角色名] [槽位]`：查看在线目标当前英雄或指定槽位英雄的下一档收益、资源差额、保护材料状态和当前有效成功率拆解；不填角色名时查自己，不填槽位时查当前英雄。
- `@HEROGRADEEVENT`：查看当前在线活动参数和剩余时间；`@HEROGRADEEVENT 80 10` 可临时把消耗倍率设为 `80%`、成功率加成设为 `+10%`；`@HEROGRADEEVENT 80 10 120` 会在 120 分钟后自动恢复默认；末尾加 `save` 会立即写入 `Server.ini`，例如 `@HEROGRADEEVENT 80 10 120 save`；`@HEROGRADEEVENT preset` 列出模板，`@HEROGRADEEVENT preset weekend [持续分钟] [save]` 一键套用模板且可覆盖持续时间；`@HEROGRADEEVENT reset [save]` 恢复为消耗倍率 `100%`、成功率加成 `+0%` 并公告在线玩家。
- 玩家英雄页“培养”：左键预览，右键拉取服务端预览并确认；英雄页会在“培养”按钮旁显示当前活动消耗倍率、成功率加成和剩余时间；旧端或缺能力连接会回退到聊天命令。

## 活动和失败补偿

- 活动消耗倍率只影响金币、材料和货币，不影响保护材料数量。
- 活动成功加成和失败补偿都会计入有效成功率，最终仍夹到 `0..100`。
- 失败补偿先按 `HeroGradePromoteFailureBonusRate` 乘以该英雄当前连败次数，再受 `HeroGradePromoteFailureBonusMax` 限制。
- 只有真实培养失败才会增加 `HeroGradePromoteFailureCount`；资源不足、配置错误、成功率为 0 且无保护不会增加。
- 自然成功或保护材料保底成功都会清空该英雄的失败补偿次数。
- GM 使用 `@SETHEROGRADE` 手动设置品质时，也会清空该英雄的失败补偿次数。
- 客户端英雄角色页会显示当前补偿次数；预览和 `@HEROGRADESTATE` 会显示补偿成功率及上限。
- 客户端英雄角色页会显示当前活动摘要；`@HEROGRADEEVENT` 开关活动或活动自动到期后，服务端会补发当前英雄信息刷新该摘要。
- `@HEROGRADEEVENT` 默认只调整当前内存，适合活动期间快速开关；末尾加 `save` 会同步写入配置文件。带持续时间且加 `save` 时，到期恢复默认后也会写回配置。

## 调参顺序

1. 先确定 `HeroMaxGrade` 和 `HeroGradeStatBonusRate`，决定最高收益边界。
2. 再设置金币基础值和金币倍率，让金币回收落在目标周期。
3. 再决定是否加入材料或额外货币，避免一开始就多重门槛。
4. 最后设置成功率和保护材料模式，明确失败体验与保护材料消耗节奏。
5. 每次调整后用“品质试算”和 `@HEROGRADECOSTS` 对比逐档与累计消耗。
