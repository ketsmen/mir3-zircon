; ============================================================
; Zircon 怪物掉落文本格式示例
; 服务端启动读取目录: .\Envir\Drops
; 读取时机: 先读取数据库掉落 -> 再读取本目录 txt -> txt 覆盖同名怪物数据库掉落 -> 构建运行期掉落缓存
; 运行时怪物死亡不读取 txt，不做文件 IO；死亡掉落只使用启动时编译好的缓存。
; ============================================================

; ------------------------------------------------------------
; 1. 文件命名
; ------------------------------------------------------------
; 每只怪物一个 txt 文件，文件名默认等于数据库 MonsterInfo.MonsterName。
; 例如:
;   祖玛教主.txt
;   沃玛教主.txt
;
; 文件名匹配时会忽略空格并忽略大小写。
; 如果多个怪物共用一个掉落文件，使用 DropPathMap.txt:
;   怪物名=文件名
;   怪物名,文件名
; 文件名可以不写 .txt 后缀。

; ------------------------------------------------------------
; 2. 基础语法
; ------------------------------------------------------------
; 标准格式:
;   1/概率 物品名 [标签...]
;
; 示例:
;   1/1 金币 Amount=1000
;   1/100 裁决之杖
;   1/20 太阳水 Amount=3
;
; 1/N 表示一次独立掉落判定，N 越小越容易掉。
; 1/1 表示必定命中。
; 物品名必须能在数据库 ItemInfo.ItemName 中匹配到。
; 物品名含空格时可以加英文双引号:
;   1/100 "Some Item Name"

; ------------------------------------------------------------
; 3. Amount=数量
; ------------------------------------------------------------
; Amount 指本行命中后产出的基础数量。
; 普通物品:
;   1/10 强效太阳水 Amount=5
; 金币:
;   1/1 金币 Amount=50000
;
; 注意:
;   普通数据库金币请使用 “金币 Amount=数量”。
;   这会保持当前 Zircon 数据库金币语义，再继续受到组队人数、玩家 GoldRate、BaseGoldRate、地图 MonsterGold、成长等级和税收影响。

; ------------------------------------------------------------
; 4. Gold / Mir2Gold
; ------------------------------------------------------------
; Mir2 兼容金币格式:
;   1/5 Gold 10000
;
; 或等价扩展写法:
;   1/5 金币 Amount=10000 Mir2Gold
;
; Mir2Gold 表示命中后先按 Mir2 金币范围随机:
;   最小 = Amount / 2
;   最大 = Amount + Amount / 2
; 然后再进入 Zircon 的金币分配、金币倍率、税收、宠物拾取等逻辑。
;
; 不想要随机范围时，不要写 Mir2Gold，直接写:
;   1/5 金币 Amount=10000

; ------------------------------------------------------------
; 5. PartOnly
; ------------------------------------------------------------
; PartOnly 表示本行只掉落碎片，不直接掉落完整物品。
; 示例:
;   1/50 屠龙 PartOnly
;
; 影响:
;   服务端会使用 ItemPartInfo 创建碎片，并记录目标物品索引。
;   货币类物品不会走碎片逻辑。
;   如果数据库没有配置 ItemPartInfo，PartOnly 不会产生碎片。

; ------------------------------------------------------------
; 6. DropSet=数字
; ------------------------------------------------------------
; DropSet 用于配合怪物实例的 DropSet 位标记过滤掉落。
; 示例:
;   1/20 祖玛头像 DropSet=1
;   1/20 特殊宝石 DropSet=2
;
; 影响:
;   只有当怪物当前 DropSet 包含该行 DropSet 时，该行才会参与掉落。
;   内部判断为: (怪物DropSet & 行DropSet) == 行DropSet
;   DropSet=0 或不写表示普通掉落，总是满足 DropSet 条件。

; ------------------------------------------------------------
; 7. EasterEvent
; ------------------------------------------------------------
; EasterEvent 表示本行只对复活节事件怪有效。
; 示例:
;   1/100 复活节彩蛋 EasterEvent
;
; 影响:
;   只有怪物对象 EasterEventMob 为 true 时才参与掉落。
;   非事件怪会跳过该行。

; ------------------------------------------------------------
; 8. Q
; ------------------------------------------------------------
; Q 表示 Mir2 任务专属掉落行。
; 示例:
;   1/10 任务道具 Q
;
; 当前处理:
;   Q 行不会导入普通世界掉落，避免任务道具错误掉到地上。
;   导入报告会统计任务专属行。
;   任务掉落应迁移到 Zircon 的 QuestTaskMonsterDetails / GainItem 任务系统。

; ------------------------------------------------------------
; 9. #INSERT
; ------------------------------------------------------------
; #INSERT 可以插入另一个掉落文件内容。
; 示例:
;   #INSERT [通用药水]
;   #INSERT [公共\祖玛公共掉落.txt]
;
; 影响:
;   启动导入阶段展开 include。
;   运行时不保留 include，不会读取这些文件。
;   支持嵌套 include。
;   如果形成循环 include，报告会记录循环错误。

; ------------------------------------------------------------
; 10. GROUP
; ------------------------------------------------------------
; GROUP 是组掉落。组本身先做一次 1/N 判定，命中后再处理组内子项。
;
; GROUP: 组内每一行独立判定，命中的都掉。
; 示例:
;   1/5 GROUP
;   {
;       1/2 金币 Amount=1000
;       1/10 太阳水 Amount=2
;       1/50 裁决之杖
;   }
;
; 影响:
;   组命中后，组内金币、物品会分别按自己的概率判断。
;   GROUP 可嵌套。

; ------------------------------------------------------------
; 11. GROUP*
; ------------------------------------------------------------
; GROUP* 表示组内先收集命中的物品候选，然后随机取一个物品掉落。
; 示例:
;   1/10 GROUP*
;   {
;       1/1 裁决之杖
;       1/1 骨玉权杖
;       1/1 龙纹剑
;   }
;
; 影响:
;   组命中后，组内命中的物品候选只随机掉一个。
;   组内命中的金币会按 Mir2 兼容逻辑直接累计，不参与“随机一个物品”的抽选。
;   GROUP* 可嵌套，嵌套组的物品候选会被摊平后参与随机。

; ------------------------------------------------------------
; 12. GROUP^
; ------------------------------------------------------------
; GROUP^ 表示按文本顺序处理，遇到第一个命中的子项后停止。
; 示例:
;   1/1 GROUP^
;   {
;       1/100 稀有戒指
;       1/20 普通戒指
;       1/1 金币 Amount=5000
;   }
;
; 影响:
;   第一行命中则只处理第一行。
;   第一行未命中才继续看下一行。
;   适合做“优先掉稀有，否则掉普通，否则掉金币”的结构。
;   文本顺序会保存为 Sequence，服务端会按顺序执行。

; ------------------------------------------------------------
; 13. 组上的标签
; ------------------------------------------------------------
; GROUP 行也支持部分标签:
;   DropSet=数字
;   EasterEvent
;
; 示例:
;   1/1 GROUP DropSet=1 EasterEvent
;   {
;       1/10 复活节宝石
;   }
;
; 影响:
;   组条件不满足时，整个组都会跳过。

; ------------------------------------------------------------
; 14. 完整范例
; ------------------------------------------------------------
; 下方是一个完整怪物掉落文件示例:

1/1 金币 Amount=50000
1/5 金币 Amount=10000 Mir2Gold
1/10 强效太阳水 Amount=3
1/100 裁决之杖
1/200 屠龙 PartOnly
1/50 活动宝箱 EasterEvent
1/20 任务证明 Q

1/10 GROUP
{
	1/2 金币 Amount=3000
	1/20 祝福油
	1/50 灵魂项链 DropSet=1
}

1/20 GROUP*
{
	1/1 裁决之杖
	1/1 骨玉权杖
	1/1 龙纹剑
}

1/1 GROUP^
{
	1/100 稀有戒指
	1/10 普通戒指
	1/1 金币 Amount=1000
}
